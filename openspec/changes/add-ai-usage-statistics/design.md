# AI 调用统计设计

## Context

动机及范围见 proposal.md，外部行为见 specs/ai-usage-statistics/spec.md。本文件对齐 eac2f21 的实现及本次审查结论，不再描述已经移除的日归档、历史范围扩展或自动备份恢复。

AI Foundation 的公共 Java/npm SDK 已发布；本统计功能和 SQLite schema 尚未发布。消费者仍通过 ExtensionGetter 获取服务，模型资源名、供应商资源名、供应商类型及远端模型 ID 各自保留含义。既有 Halo Extension 数据、Secret 引用、模型解析流程和公共 SDK 类型不变。

## Goals / Non-Goals

**Goals:**

- 解释逻辑调用及其步骤、批次、重试的已报告用量，区分未知用量和统计事件丢失。
- 数据库 I/O 不在模型调用路径上执行，存储故障尽量局限于统计能力。
- 历史查询精确遵守时间边界，按用户时区分桶；以保留调用事实换取实现和查询语义的直接性。
- 控制异步内存、连接、重试和维护批次，保持数据库文件生命周期明确。

**Non-Goals:**

- 零丢失或财务计费账本；缺失的供应商用量不估算。
- 自动备份、恢复、损坏修复、日汇总归档及历史范围提示。
- 全生命周期磁盘硬上限、reset 自动缩盘，或未经测量的高并发和百万规模性能承诺。

## Decisions

### 分离协议、观察和存储

1. `ProviderUsage` 归一化 Chat Completions、Responses、Messages 和 embedding 协议。输入包含缓存读取及创建，输出包含推理；已包含的子项不重复相加。内部 nullable Long 保留未知，公开 SDK 仍使用既有类型。
2. `service.observation` 表达逻辑调用、实际执行、终态及规范化用量。运行时只依赖观察接口，不依赖 SQL 或保留策略。外层 audit 捕获逻辑调用，执行边界记录步骤、批次及每次尝试；只观察最外层结果会遗漏重试和部分失败的用量。
3. `UsageStatisticsService` 消费有限的统计字段，异步持久化。观测回调异常不替换业务结果；provider 协议解析仍属于原业务响应链路，不能把回调保护描述为任何错误都绝不影响模型执行。

### 订阅、流式投影和兼容性

- 非流式 delegate/middleware 在订阅时执行，同一个 publisher 重复订阅会重新进入该链，同步抛错成为响应式错误。每次订阅有独立逻辑调用；这与原有组装期执行时机不同。
- 共享流的投影共用一次会话和一次上游执行；把首个订阅者的 Reactor Context 传给上游。不为采集统计额外订阅任何投影。无结构化输出时，空 output() 不触发调用。
- 执行用量优先，避免父子双计数；缓存短路没有实际执行时可以采用调用结果用量。投影先结束、最终结果后到的情况仅允许受限补全，不能覆盖已明确终态。
- 取消时协调已启动执行的终止事实，不等待数据库；累加器不随执行数保存全部历史。非流式生成内部使用 provider stream 时采用整步 deadline，连续 chunk 不能延长时限。
- 标准化结果也经原 mapper 返回 SDK。Messages input 包含缓存，部分旧适配器零填充改为未知，usage-only chunk 可以补回此前缺失的用量。API 签名兼容不代表数值及执行时机完全兼容，发布处理见 Migration Plan。

### 保留调用事实，精确查询

`ai_calls` 长期保留标量统计事实及少量诊断元数据，不包含请求或响应正文。执行详情单独保存在 `ai_model_executions`。与 UTC 日归档相比，这避免了部分历史日期不能拆分、迟到终态重复汇总和跨时区重新分桶的问题，也删除了 sourcePlan 和精度披露字段。

汇总、趋势、排行按逻辑调用 startedAt、状态和维度查询精确的 `[from, to)`；所有尝试的已知用量归属逻辑调用，跨日执行也归入该调用开始日。调用列表和单条详情在服务层限制最近 90×24 小时，但不删除统计事实。分页游标绑定原始请求（含时区），保留期边界移动时仍可继续翻页。

执行清理使用 UTC 当天零点减 30 天的截止点，仅删除父调用已结束的记录；每批最多 2048 条，批间让出 writer。初始化一小时后首次维护，之后每 24 小时调度。不再写日汇总表或删除调用事实。

### UTC 存储、IANA 时区分桶和展示

时间点以 epoch 毫秒存储。前端使用浏览器时区，把本地日历日期的起点和次日零点转成 UTC 请求；预设最近若干天仍是截至刷新锚点的时间窗口。服务器校验 timeZone，省略时使用 UTC；省略 to 时仍使用下一 UTC 午夜，保证同一 UTC 日内无参数分页的默认范围稳定，from 默认提前 30 天。Console 显式发送范围。

SQLite 不维护 IANA 规则，因此后端按 ZoneRules 偏移变化拆分查询区间，每段在 SQL 内聚合，Java 只解析日界和合并聚合桶。日桶按本地自然日归并；小时桶在偏移切换时可成为部分小时，重复小时使用不同 UTC instant 标识。没有逐调用加载到 Java，也没有固定 24 小时自然日假设。

趋势轴、tooltip、热力图日期键共用查询时区。小时 tooltip 显示 offset；柱宽考虑 23/25 小时日及半小时 DST。热力图与 API 共用刷新锚点，从第一格本地午夜查询到该锚点，以本地日历递增网格。不恢复 UsageRangeAlert 或其他历史范围警告。

### 有界写入和健康状态协调

- 8192 容量的事件队列、单 writer、每批最多 128 个事件的事务、最多三次写入尝试；持续流量下每轮八批后让出线程。关闭排空阶段不使用这一公平性批次上限。
- 幂等事件允许安全重试；非存储性坏事件可拆分隔离，存储失败不逐条反复探测。容量不足时丢弃统计并记录健康状态，不让模型调用等待落库。
- 活跃会话与已结束但待健康落盘的会话有界跟踪。缺失 start、complete 标记和健康计数同事务写入；检查点期间再次变脏时保留待处理记录，避免重启重复计数。
- 丢失终态在写队列清空且检查点完成后补偿，排除仍活跃会话；启动将遗留 IN_PROGRESS 结算为 ABANDONED，保留已落库用量。
- reset 事务清数据并推进 epoch，再退休旧内存事件和会话；没有旧快照恢复路径。

这些状态协调是异步尽力记录的成本，不能把整个统计子系统称为简单埋点。暂不增加管理器层次或自动重连框架。

### SQLite 生命周期及查询资源

固定数据库及 WAL/SHM 路径。三者均不存在才创建新库；现有主库必须可识别且通过只读版本校验和 quick_check，孤立辅助文件、空库或损坏不会被静默覆盖。初始化失败停用统计，运行期识别 corruption 时同样停用，模型调用继续。

WAL、synchronous=NORMAL、busy_timeout=5000、自动 checkpoint 1000 页、journal_size_limit=16 MiB。最后一项不限制活动 WAL 的峰值，长读事务可能推迟 checkpoint。

两个读工作线程、有界等待队列，最多复用四个读连接；查询在独立读事务中取得一致快照，结束后提交或回滚。单 writer 及生命周期锁协调 reset/关闭，admission 锁不跨数据库 I/O。关闭先停止接收并排空，必要时 interrupt SQLite 操作，再回收活动和空闲连接。有分阶段等待上限，没有整个启动或关闭流程的严格总 deadline。

调用列表和详情使用时间、调用方、模型及 call_id 索引。聚合使用 UTC 小时开头、覆盖筛选维度和计数的宽索引，避免逐条回表。当前本地趋势 GROUP BY 仍可能使用临时 B-tree；不能声称已经消除百万行排序。相比预聚合，直接查询保留了精确任意边界，代价是扫描成本随范围内调用数增长。

## Risks / Trade-offs

- **长期容量增长** → 接受调用事实及索引永久增长的设计；30 天执行清理减少一部分数据，90 天访问窗口并不限制数据库大小。reset 逻辑删除后空闲页可复用，但不保证文件缩小，也不适合作为磁盘耗尽时的可靠释放手段。
- **聚合性能未达既定预算** → 保留覆盖索引、有界读线程和异步写入；如实记录规模结果，不通过放宽断言或新增复杂查询分支宣称达标。进一步容量与性能方案由实际负载推动。
- **生命周期耗时** → 启动同步 quick_check 随库规模增长；关闭已有 interrupt 和阶段等待，但不能承诺总耗时最多五秒。规模样本的 quick_check 约四秒。
- **故障状态收口** → 回滚失败会关闭不再安全的连接；上层对不可复用 writer 的停用传播仍有待补充服务级回归和小修，不把当前实现描述为所有永久故障都能自动正确终止接收。
- **兼容性变化** → 明确公布 inclusive usage、未知值和订阅期 middleware 行为，避免消费者重复相加或依赖旧执行时机。
- **维护资料与实现漂移** → 后续表结构、保留策略、指标语义或生命周期变化同时更新本变更文档及测试，不能按已删除的归档/备份设计恢复功能。

## Migration Plan

- 本功能首次发布前维持单一 schema v1，不迁移开发期试验数据库，也不自动删除或重建用户数据库。没有 Halo Extension 数据迁移，公共 Java/npm SDK 类型保持不变。
- 已发布 SDK 的消费者可能依赖旧 Messages input 口径、零填充或 middleware 组装时机。首个包含本变更的版本（版本号尚未确定）需在发布说明明确行为兼容性影响：缓存计数是 inclusive input 的子集，不再额外相加；缺失计数需按未知处理；依赖单次组装或缓存 publisher 的 middleware 需检查重复订阅行为。不能把这些变化笼统声明为无影响。
- 首次发布后改表或索引必须递增 schema version，提供明确旧版本升级；迁移 SQL 与版本更新同事务，保留统计数据和 epoch，失败回滚且不重建。只读版本门控、升级/重开/回滚/更高版本拒绝都需回归测试。
- 插件版本回退必须使用兼容的统计 schema；不自动降级数据库或恢复快照。损坏文件由管理员按需离线处理。

## Validation status

截至 2026-10-14，eac2f21 的完整构建和远端 CI 通过：后端 1111 项（1110 通过、1 项规模测试默认跳过），前端 322 项通过，类型检查和 Lint 通过；纽约和加德满都进程时区各 59 项针对性测试通过。覆盖精确历史边界、DST、非整点偏移、队列饱和、重启去重、reset 和关闭等回归。生成的 OpenAPI 与客户端已同步。

显式运行百万调用、五百万执行的规模任务两次，均未通过现有聚合 P95 ≤500 ms 验收。复测汇总 P95 约 546 ms，UTC 趋势约 1776 ms，Kathmandu 趋势约 913 ms；首轮在负载波动下更慢。入队 P95 约 0.007–0.008 ms 只测部分路径，不能代表完整模型调用开销。约 1.96 GB 文件包含执行数据、索引和删除后空闲页，不能外推纯调用事实单条成本。

候选 SQL 的一次真实库比较没有证明非整点时区能在低复杂度下稳定达标，未合入优化。功能/静态复审通过不等于规模性能验收通过。当前时区和保留策略下的真实 Console 浏览器验收需重新留证，不能沿用旧归档版本的完成标记。
