# 模型能力目录

AI Foundation 使用 [models.dev](https://models.dev) 补全模型能力、参数映射和限制，
减少逐个模型配置的工作。可用模型仍从你配置的供应商获取，目录不会额外添加账号无权使用的模型。

## 使用方式

1. 在供应商页面选择「从供应商获取模型」，查看可用模型及自动补全的能力。
2. 导入模型，或在创建、编辑模型时选择模型 ID 和调用接口，表单会自动匹配目录参数。
3. 根据需要调整配置并保存。手动设置优先于目录数据，后续匹配会保留你的覆盖配置。

插件启动后会在后台同步目录，此后每 24 小时检查一次。需要获取最新数据时，
可在模型导入弹窗中点击「刷新能力目录」。网络不可用时，插件使用本地缓存或内置副本。

**刷新目录不会直接修改已保存的模型。** 要应用最新目录参数，请打开对应模型的编辑表单并保存。
模型调用使用已保存的配置，不依赖实时访问 models.dev。

## 自动补全的内容

| 模型类型 | 可补全的内容 |
| --- | --- |
| 语言模型 | 工具调用、结构化输出、推理和媒体输入能力；采样参数支持、推理映射、Token 限制及部分供应商原生选项 |
| 图像生成 | 当前调用接口支持的图片输出格式，以及目录提供的上下文、输入 Token 限制 |
| Embedding、Rerank | 模型类型及目录提供的上下文、输入 Token 限制 |

目录信息还需符合当前调用接口支持的范围。模型在目录中声明某项能力，并不代表所有调用接口都支持它。
图片数量、尺寸、比例、Embedding 维度和 Rerank Top N 等参数，仍使用对应的参数映射配置。

当供应商只返回模型 ID、没有明确模型类型时，目录也会辅助识别类型，例如将嵌入模型识别为 Embedding。

## 调整模型配置

模型编辑页面按用途提供以下配置：

| 配置区域 | 用途 |
| --- | --- |
| 模型能力 | 设置工具调用、结构化输出、推理及媒体输入、输出能力，供模型筛选和 SDK 调用使用 |
| 参数映射 | 设置 Temperature、Top P、Top K、推理等统一参数如何转换为供应商请求参数 |
| Token 限制 | 设置上下文、输入、输出 Token 上限及推理预算范围 |
| 供应商原生参数 | 设置原生工具严格模式、响应存储、流式用量统计、工具选择模式等接口选项 |

能力信息按以下顺序采用：**手动配置 → 供应商明确声明 → 模型目录 → 内置默认值**。

参数映射按以下顺序采用：**模型手动配置 → 供应商手动配置 → 模型目录 → 供应商内置默认值**。
选择「继承」时使用下一层配置。目录未声明某个参数表示未知，不等于不支持；
明确声明不支持的参数会受到限制。需要调整时，可手动覆盖对应映射或限制。

## SDK 调用

SDK 开发者继续使用统一参数，无需自行读取 models.dev 或判断用户选择了哪个供应商的模型。
AI Foundation 根据已保存的模型配置转换请求参数。

例如，通过 Java SDK 表达较高的推理强度：

```java
GenerateTextRequest request = GenerateTextRequest.builder()
    .prompt("分析迁移方案的风险")
    .reasoning(ReasoningOptions.effort(ReasoningOptions.Effort.HIGH))
    .build();
```

`LOW`、`MEDIUM`、`HIGH` 表达相对强度，由模型的推理映射转换为实际请求值。
例如，模型提供 `low/high/max` 三档时，可分别对应这三层意图。
只有推理开关的模型按开关能力处理；不保证每个模型都有三个不同的强度档位。
具体调用方式见 [生成与流式文本](./sdk-core/generating-text.md#推理内容)。

调用时还需注意：

- 显式设置的输出 Token 数超过模型上限会报错，上限本身不作为默认生成长度。
- 上下文和输入 Token 上限供调用方规划请求，SDK 不自动校验输入 Token 数。
- 不支持原生结构化输出时，SDK 可使用提示词和本地结果校验完成结构化输出。

更多示例见 [图像生成](./sdk-core/image-generation.md)、
[Embedding、Rerank 与 RAG](./sdk-core/embeddings-reranking-and-rag.md)。

## 没有匹配到目录时

自动匹配要求供应商、模型 ID 和调用接口一致，模型 ID 区分大小写。
目前支持 OpenAI、DeepSeek、Kimi、百炼、硅基流动、智谱 / Z.AI、豆包、
OpenRouter、AIHubMix 和 TokenHub 的已适配官方接口；具体模型还需存在于对应目录中。

自定义代理地址、Coding Plan、通用 OpenAI 兼容供应商、Ollama 和其他私有部署不自动匹配。
修改 Chat Completions 的聊天路径后，该接口也不使用目录补全。

没有匹配结果时，仍可正常配置和调用模型。检查供应商类型、API 地址、模型 ID 和调用接口，
或直接在模型配置中设置能力与参数映射。修改模型 ID、供应商或调用接口后，原来的目录参数不会继续套用。

## 更新内置副本

从源码构建插件时，可在项目根目录更新随插件发布的离线目录：

```bash
./gradlew updateModelsDevSnapshot
```

仅校验本地副本：

```bash
./gradlew verifyModelsDevSnapshot
```

更新后重新构建插件，新副本才会随插件发布。普通构建使用仓库中已有的副本。
